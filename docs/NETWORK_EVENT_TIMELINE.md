# Network Event Timeline

NEO records network activity as persisted `NetworkEvent` entries. The timeline is an additive layer over the existing scan history, device detail, and 3D map surfaces.

## Event Schema

Each event includes:

- `id`
- `timestamp`
- `type`
- `severity`
- `relatedDeviceId` or `relatedRouterId` when applicable
- `title`
- `detail`
- `sourceScanId` when generated by a scan

Supported event types are:

- `scan_started`
- `scan_completed`
- `device_first_seen`
- `device_returned`
- `device_went_offline`
- `device_trust_changed`
- `device_renamed`
- `device_flagged`
- `router_status_changed`
- `scan_failed`
- `network_context_changed`

## Retention

Events are persisted in the existing app state under `networkEvents`.

Retention is bounded to the newest 500 events and events from the last 90 days. The helper that appends events applies both limits so the stored app state does not grow without bound.

## Scan Delta

The latest scan comparison is persisted as `lastNetworkScanDelta` and includes:

- `newDeviceIds`
- `offlineDeviceIds`
- `returnedDeviceIds`
- `changedDeviceIds`
- `labelChangedDeviceIds`
- `statusChangedDeviceIds`
- `trustChangedDeviceIds`

## AI-Ready Selectors

`lib/network/networkEvents.ts` exposes selectors for future assistant features:

- `selectEventsFromToday`
- `selectRecentChanges`
- `selectSuspiciousChanges`
